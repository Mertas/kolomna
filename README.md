# Kolomna

Изометрический градостроительный симулятор на Rust.
Процедурный мир (река, холмы, рощи), изометрия на wgpu,
городской редактор (дороги с перекрёстками и зебрами, кварталы-колодцы, парки),
уличная мебель, вариации домов и диорама-кромка.

## Имя

Коломна — исторический район Санкт-Петербурга между Мойкой, Фонтанкой, Пряжкой,
Большой Невой и Крюковым каналом. Здесь прошли юношеские годы Пушкина (1817–1820,
дом Клокачёва на Фонтанке), им посвящена поэма «Домик в Коломне»; здесь же живут
герои гоголевского «Портрета». Очерк с источниками: [docs/research/kolomna.md](docs/research/kolomna.md).

## Правовая рамка (коротко)

- Код — только собственный, чистый Rust.
- Вся графика процедурная или свободная (шрифты — OFL); сторонние ассеты
  не используются и в репозиторий не входят.
- Приложение работает только с собственными процедурными данными:
  внешние файлы не читаются вовсе.
- Имя, код и архитектура — свои.

## Структура

    crates/
      kolomna-render  — генерация мира и рендер (wgpu): террейн, река, рощи, дороги, дома, изометрия
      kolomna-app     — приложение (окно winit, редактор, exe)

## Быстрый старт

    rustup default stable-x86_64-pc-windows-gnu   # MSVC не требуется — сборка под GNU-тулчейн
    cargo build

    # приложение (окно редактора): мягкий зум колесом, повороты средней кнопкой, навигация краями окна
    cargo run -p kolomna-app

    # одиночный кадр без окна (для проверок)
    cargo run -p kolomna-app -- --shot out/city.png

Без аргументов `kolomna-app` открывает процедурный мир; `KOLOMNA_SEED=<u64>` выбирает
другое зерно генерации. Готовый exe в репозиторий не входит (собранные бинарники
игнорируются). Собрать релиз: `cargo build --release` → `target/release/kolomna-app.exe`.

## Сборка на Windows (GNU-тулчейн)

Известная особенность `stable-x86_64-pc-windows-gnu`: self-contained gcc из rustup
собран с префиксом `/c/buildroot` и сам не находит свои стартовые файлы — линковка
падает с `ld: cannot find crt2.o`. Лечится файлом `.cargo/config.toml` (в репозиторий
не включён — он машинозависим), который указывает тулчейну, где искать `crt2.o` /
`libkernel32.a`:

```toml
[env]
LIBRARY_PATH = "C:\\Users\\<user>\\.rustup\\toolchains\\stable-x86_64-pc-windows-gnu\\lib\\rustlib\\x86_64-pc-windows-gnu\\lib\\self-contained"
COMPILER_PATH = "C:\\Users\\<user>\\.rustup\\toolchains\\stable-x86_64-pc-windows-gnu\\lib\\rustlib\\x86_64-pc-windows-gnu\\lib\\self-contained"
```

Если в этой папке нет `crtbegin.o` / `crtend.o` — их можно взять из w64devkit
(gcc 14.1) и доложить в тот же `lib/self-contained`.

## Управление (окно)

- колесо — мягкий зум; средняя кнопка — мягкий поворот; Shift+средняя / ЛКМ / ПКМ — перенос
- края окна — плавная навигация; WASD/стрелки — перенос; Q/E — поворот на 90°; R — сброс; Esc — выход
- редактор: 1 — камера, 2 — дороги, 3 — кварталы, 4 — парки; ЛКМ — точка, ПКМ/Backspace — убрать,
  Esc — закончить цепочку / выйти из режима; кварталы и парки снапаются к ближайшим дорогам
- в заголовке окна: fps, зум, угол

## Dev-проверки (examples)

В `crates/kolomna-render/examples` живут headless-проверки рендера и геометрии
(jprobe, jdump, hcmp, rdsplit, faccensus, roofcensus): сцены синтетические,
внешние файлы не нужны. Запуск стандартный: `cargo run -p kolomna-render --example jprobe`.
